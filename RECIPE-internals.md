# Wickline — internals

Build details behind [RECIPE.md](RECIPE.md)'s Built from, needed only when rebuilding Wickline: the stored layouts, the module map with per-module notes (with how a move waits), the sessions, the logos and the icon drawing. Each request, the fields it reads and each source's detailed rules are in [RECIPE-sources.md](RECIPE-sources.md). Hosts, programs and storage locations are named in RECIPE.md; nothing here changes them.

Each source's requests and fields: [RECIPE-sources.md](RECIPE-sources.md#network-requests).

## Sessions

Futures (`WTX&`): sessions from the line's `sourceTradingPeriods` while `now` is on their own trading day, else TAIFEX's hours (night 15:00–05:00, day 08:45–13:45, Taipei, each opening Monday to Friday, but not on a listed closed day, whose night reads closed). Inside a session the real-time rules apply (`Live`; the day close with no night trade reads `報價停在 13:44` from 15:00, asked every 10 s, then closed from 15:10); between sessions, and over the weekend, it reads closed with its last trade time (`已收盤 · 05:00`), with no stale check and no wake for one.

The open detail fetches nothing, so it keeps the closure mark it opened with only until the mark's end (`closureUntil`, which `closureOf` in `closures.js` gives beside the mark from the same rules table), then reads the quote without it:

| Mark | Read at (Taipei) | Ends |
|---|---|---|
| any stock mark | any time | the next 00:00 |
| a future's `listed` | any time | 05:00 the next day (the night it removes) |
| a future's `noTrades`, `nightNoTrades`, `nightRemoved` | 00:00–05:00 | 05:00 that day |
| a future's `noTrades` | 05:00–15:10 | 15:10 that day |
| a future's `noTrades`, `nightNoTrades` | 15:10–24:00 | 05:00 the next day |

An open detail wakes, one task at a time, at the earliest of its quote's next edge, its mark's end and the stale moments of what it shows a state for (a real-time price, not a pair's; a line that is another source's real-time quote), none for a quote that already reads stalled (a cached one); never at an inference deadline, since it gets no new answers; each sleep is at most 10 min and then rereads the clock; it redraws only when a wake is reached and ends with the dialog.

## Stored layouts

The storage RECIPE.md lists, field by field:

- `shared("wickline.watchlist.v1")`: `{ version: 1, symbols: [...], paused }`.
- `shared("wickline.settings.v1")`: `{ version: 1, language: "en"|"zh-TW"|"zh-CN"|"ja"|"ko", colors: "auto"|"red-up"|"green-up", languagePromptDismissed, keyRev, sources: { us: { provider: "yahoo"|"finnhub", finnhubUrl, budgetPerMinute }, tw: { mis, yahootw, misUrl, misAck: { version } | null, yahootwAck: { version } | null, provider: "yahoo"|"mis" }, crypto: { binanceUrl } } }`.
- `shared("wickline.detail")`: `{ symbol, token, seq, quote }`, `{}` once cleared; written only by the copy holding its `token`. The quote carries its line's times as `timesPacked: { t0, d }`, seconds: the first time, then each step, never `times`; an undecodable or mismatched value is adopted without times. Each `setShared` re-renders every copy of every mod: about two per 10 s with MIS and Yahoo 奇摩股市 on.
- `data/wickline/secrets.json`: `{ "finnhub.key": "<key>" }`.
- `localStorage` `wickline.filter`: `all`, `us`, `tw`, `hk`, `cn`, `jp`, `kr`, `crypto` or `other`; each use in a `try`.

## Modules

One bullet per module: what it holds, then build notes. A one-line map by group is in [CONTRIBUTING.md](CONTRIBUTING.md#code-map).

- `main.js`: the one `View`. It picks the mode from `props()`, builds the hosts, runs the loops and the command loop, makes every input outside `render` and sizes the panel (`layoutFor`). The dialogs are the same mod; settings starts no loop, the detail one redraw task (RECIPE.md's Detail). The `View` is `gpui-kit`'s `View`, with `gpui-base` `v_flex`, `h_flex`, `InputState`. The detail dialog opens with `openOverlay({ mod: "wickline", kind: "dialog", width, props: { detail, token, wide } })` (`wide`: `canCarryBook(detail, settings)` in `layout.js`, 720 else 440; the dialog keeps it) (`ui/detail-dialog.js`; `detail` is `Watchlist#detailQuote`: the row's quote as shown, with its `error`, its overlay's `fallback` and its mark's end `closureUntil`, read at one moment), the settings dialog as a modal one with `settings: { tab, health }` (`ui/settings-dialog.js`); draft, inputs and Save stay on the view. `openDetail` writes before `openOverlay`; each loop's `changed` runs `handOver` (one synchronous step); `render` adopts (`adoptDetail` wakes `followDetail`); `close` clears its own. Only `detailStore` touches the key.
- `handover.js`: the detail's hand-over (`nextWrite`, `adopt`). `nextWrite` writes `seq + 1` while the key holds its token and `contentKey` differs: the quote, or, paused, all but `closure`/`closureUntil` (paused loops re-mark rows at each edge). `adopt`: own token, higher `seq`. `packTimes` (written values only) keeps whole-second times as `timesPacked`, else drops them; the opening copy keeps the plain quote, so `contentKey` compares plain with plain. `unpackTimes` (in `adopt`) drops any `timesPacked` or plain `times` and gives `times` back only from whole-second steps, one per value of the line.
- `ui/`: functions of the view and theme returning elements. `panel.js` draws band, sidebar and table, with the list, the market filters and the footer; `header.js` holds the header's pieces (`brand`, `headerIcons`, `addField`, …) and `rows.js` the rows both layouts share (`rowFrame`, `sidebarRow`, `tableRow`, …); `parts.js` holds stateless helpers (`chart`, `priceBox`, `inset`, `toggle`, …); `detail-dialog.js`, `settings-dialog.js`. Built from `gpui-kit` `div`, `svg`, `PathBuilder`, `Background`, `window.paint_path` and `gpui-base` `h_flex`, `v_flex`, `Input`, `Checkbox`, `Switch`. `rowFrame` (`rows.js`) holds the handle, `×`, hairline and drop line. `chart` paints each by `window.paint_path(...)` as an absolute layer over a sized `div`: the line (`PathBuilder.stroke`, 2px with the fill by default, else 1.25px; 1.5px in the sidebar and table), the rule (`.dash_array([3, 3])`), the fill (`PathBuilder.fill()`, closed along the bottom to the line's end), both only with 2 or more points; the price's dot is an absolute `rounded_full` `div` (4px, `{ dot: 6 }` in the detail) in a layer inset by half its size, so it stays whole at either end. `chartGeometry(series, reference, chartLayout(quote))` (`chart.js`) spreads the points over the extent as `[x%, y%]`, 8% headroom, the previous close (whenever positive) and the dot in range; `chartLayout` and `sessionProgress` (`chart.js`) give the extent and the dot from the trading day: the regular period or the exchange's hours less lunch, a future's two segments of its trading day (its periods', else TAIFEX's), none for a pair, FX or `=F`. The detail dims (`detailDimmed`: cached or stalled) with one `opacity(0.5)` each on its price line and activity (one column's volume; two's grid, inner/outer bar and book; ladder digits in the interface font). The detail passes `chart` a `crosshair` option: the box takes the id `bw-detail-chart`, `on_mouse_move` hands the pointer's x as a share of `bounds.width` (clamped 0…1) with that width to `view.chartPointer` (`{ share, width }`, cleared on leave and whenever the chart is not drawn), and the dialog redraws only when the nearest point or the width changes; its mark adds three absolute layers after the others: the 1px `dim` line, the 6px dot in the point's change color centred on the point in the full box (not the price dot's inset layer), and the card's opaque plate (`px(6)`, `py(4)`, `rounded(3)`, `whitespace_nowrap`; the 11px `dim` time over the 12px semibold price and the change 6px after it; only its text takes the detail's 0.5 opacity when dimmed or over a cached line, so the line never shows through) at `left(spot.left)` or `right(spot.right)` and at `top(level.top)` or `bottom(0)`, from `crosshairLevel(y, 140)`. The option is passed only when `crosshairAt` can place a point (a line with one time per point); otherwise the pointer is cleared. The list's charts take no option.
- `format.js`: `rowName`, `displayName`, the change and a bare price, `changeTone`, and number, date and time formatting by hand. `lineDate(quote, lang)` (the detail writes it at `text_size(10.5)` in `dim` 2px below the chart's left end, outside the box, only when there is one): `formatDate` of the line's first point; "" with fewer than two points or times not one per point.
- `chart.js`: chart geometry (`chartGeometry`, laid out by `chartLayout` and `sessionProgress`; see `ui/`) and the crosshair. `crosshairAt(geometry, times, share)` picks the drawn point nearest the share (clamped), the later one on a tie, so past a line that ends early it holds on the last point; null without a line, with times not one per point, or a share that is not finite. `crosshairLabel(quote, index, lang)` gives `time` (`formatTime`, always after `formatDate`, so a line across midnight reads unambiguously), `price` (`number`) and the change against the previous close, null without one. The card's size is estimated only to pick its place and catch a card too wide for both sides: its wider line, the time at 6.5px a character or the price and change at 7.5px plus 6, then 12 of padding; about 40px tall. `crosshairSpot(x, label, width)`: `{ left }` 6px right of the line, else `{ right }` placed by its right edge, so the 6px gap holds in any layout font, else `{ left: 0 }`. `crosshairLevel(y, height)`: the card's middle at the point, `{ top: 0 }` near the top, `{ bottom: 0 }` (placed by its bottom edge) near the bottom.
- `watchlist.js`: the list and one loop per source (`runProvider(id, io)`). Host: `load`/`save`, `settings`, `fetch`, `loadSecret(name)`, `now`, optional `shown()`. A row shows `mergeOverlay(base, pickOverlay(...), line)` (`overlay.js`). The host's `shown()` defaults to true and comes from `layout()` for a docked block. `main.js` runs each source's `runProvider(id, io)` in its own `cx.spawn`, with its `cx.sleep` and `cx.notify()`. Each source keeps a cooldown and a problem (`problems()`: status lines, the dialog's `health`) and quotes the symbols of its markets and kinds, within its `cap` (first in list order). Lines carry `times` (ms, one per value, absent when unknown or empty); Binance's quote keeps its line's `times` with its `series` across tickers until the next klines answer. An overlay source writes its own prices and errors (by symbol, then source), never the base quotes; the `line` a row merges is that source's same-day line or the base's, the latter only when the base's time and the overlay price's are on the same side of the base's regular period's start (else no line, no `chartSource`, no `chartCached`). The price appended to an overlay's own timed line is at `max(tradeTime ?? timestamp, last time)`, floored to whole seconds; an own line without aligned times gives none, and the base's times go only with the base's line. `lastAt` alone judges a frozen line, never `times`. A source that is a symbol's sole source (Yahoo 奇摩股市 for a TW-only symbol or a future) gives that row its errors and periods; its price stays in the source's own slot. An index whose market resolves wakes each overlay source it joins, never a full restart. The Finnhub key, reread when `keyRev` changes, stays in memory and requests, never `config()`. Edits (`restore` undoes `remove`) are synchronous, bump a revision (a round in flight drops late results) and wake every loop, as `sync()` does for another copy's edit. A source declares `id`, `markets`, `kinds`, `overlay`, `cap(config)`, `manualRefresh`, `spacingMs`, `intervalMs`, `linesMs`, `linesPerRound`, `requests` and `decode` (`providers/provider.js`); `Watchlist.serves` decides which symbols it gets, and a `QuoteError` with `stopsSource` stops its loop. Between rounds a loop also wakes at the shown rows' next edge (`edgeAt`, from `freshness.js`'s `nextEdge`; `{ openings: true }` for openings only), the moments a row's session or day can turn: a period's pre, regular and post bounds (else a Taiwan or US quote's exchange hours on a trading weekday; not FX), the exchange's lunch inside the regular period, a future's segments (its line's and TAIFEX's table, which alone holds the 15:00 night once `ownPeriods` drops the line's), FX's Friday and Sunday 22:00 UTC, each row's own midnight (Taipei for a Taiwan row, else local; DST-safe), and for a Taiwan stock with a real-time source on (`twRealtime`) the call auctions' edges (08:30, 09:00, 13:25, 13:30 Taipei on today's and the next Taipei date, each only on a weekday; none on a listed day) and MIS's flag lapse (`auctionAt` + 2 min). Openings (a regular start, a lunch's end, a segment's start, FX's Sunday 22:00) also end the interval and start a round; any other edge only redraws. A hidden copy skips edges until `wakeMissed()`. Activity (`ACTIVITY_FIELDS`): `overlay.js`'s `mergeOverlay` drops the base's unless the overlay is its source, or sends no volume over a real-time base (`isRealtime`: Finnhub's `AAPL` keeps Yahoo's) that is not cached and is on the price's side of its regular start; `marked` drops a Yahoo Taiwan stock's while a real-time source is on, then the book (`rowBook`): a held row's auction book, else a `preopen` one in its window, else its own (a stock's Yahoo 奇摩股市 book fetched in an auction window and traded that day: `auction` while that window lasts, else none), else empty under `noLevels`.
- `overlay.js`: which source's price a row shows and how it merges, pure. `pickOverlay(byProvider, order, now, base, flagged)`: the first live overlay in priority order, else the newest, or none when a real-time base is no older; MIS's held price yields to another overlay of its Taipei day while flagged. `mergeOverlay(base, overlay, line)`: the overlay's price over the base's name, currency and periods, with the line and activity rules in the `watchlist.js` entry.
- `quotes.js`: symbol rules, `priceLimit`, error codes with their English texts, the request headers and the cleaners for what a source sends. `cleanTimedSeries(values, times)` keeps the positive values (the last 400) with their times; `times` is null when not one per value or any kept one is not positive, so a value is never dropped to keep times. `cleanSeries` is its values alone.
- `secrets.js`: reads, writes and removes the key file (RECIPE.md's Storage) and reads its last four, given `fs/promises`, a `system` (with the one `chmod`) and the folder. The `system` holds `platform()` (from `window().platform`) and `chmod(path)`, the one `exec` under RECIPE.md's Programs, run after each write on `macos` and `linux` only; the folder is `appHome()` + `/data/wickline`. The file goes with its last key; save and remove resolve false when chmod failed (the key is still written).
- `layout.js`: the panel sizes of RECIPE.md's What you see as constants, `layoutFor(size)`, `sparkWidth`, `tableColumns(width)` and `wantsCard`. `TABLE_COLUMNS` (id, width, alignment); `tableColumns(width)` gives the ids that fit, in display order; `nameWidth`.
- `panes.js`: where a move goes and when it has arrived (`returnPane`, `newWicklineTab`, `waitUntil`, `dockOf`, `isShown`, `blockYields`, `staleDockTab`).
- `moves.js`: makes the moves; host: `panes`, `layout`, `run`, `shared`, `setShared`, `focused`. Runs only `tab.new`, `tab.select`, `pane.split`, `pane.close`, `layout.hide`, `layout.show` and `layout.select`. Its `syncDock` (from `render`, for the view) and `onScreen` (for the loops) read the block's place, yield and shown state, both clearing a stale `wickline.dockTab`.
- **Moves wait**: the old copy closes (or the block collapses) only once `panes()` or `layout()` shows the new place: a new Wickline pane outside the old tab (in the target tab going back), one in a tab that did not exist before (`newWicklineTab`; `ctrl-alt-b` into an existing tab never counts), or the panel shown (`isShown`). A task looks every 50 ms for about 1.5 s; failing that, nothing closes, collapses or is stored, and the icon works again. While a move waits, clicks do nothing (`moving`).
- `markets.js`: a symbol's market (`marketOf`; an index's from its exchange, `resolvedMarket`) and kind; Yahoo's exchange codes and their delays (`exchangeRule(exchange, symbol)`); the exchanges' hours; the filters' market order (`marketOrder`). `marketOf` judges by form; the kinds are stock, index, pair, future (`WTX&`, Taiwan by form) and other. `exchangeRule(exchange, symbol)` gives `{ realtime, delayS, lunch, futures, fx }` (`.TW`/`.TWO` TAI's if unlisted, `=F`/`=X` without one); `TYPICAL_EXCHANGE` (us NMS, tw TAI). `TAIFEX_HOURS` is TAIFEX's own table (day 08:45–13:45, night 15:00–05:00, Taipei minutes, Monday to Friday openings), apart from Yahoo Finance's `RULES`: `freshness.js` reads a future's session from its line's segments, else from it (`futuresSegment`, `sessionName`), and `watchlist.js` cuts a wait at its next opening (`edgeAt`, from `freshness.js`'s `nextEdge`). `TWSE_HOURS` (09:00–13:30 Taipei, TWSE and TPEx) and `US_HOURS` (09:30–16:00 New York, its offset from `usOffsetMin` in `time.js`: daylight saving by hand, second Sunday in March to first Sunday in November) give a Taiwan or US quote its session only until Yahoo's periods arrive (`hoursWindow` in `freshness.js`); a today's price that had stalled by the close keeps reading stalled after it, never closed (`stoppedBeforeClose`); any other market stays unknown, and the view shows no word for it. `ownPeriods` drops a line's `segments` once `now` is on a later trading day than theirs, so from 15:00 the night is read from the table. Yahoo's exchange codes (closed): US DJI, SNP, NIM, NMS, NYQ, PCX live, CXI 20, NYS, WCB 15; Taiwan TAI, TWO 20, TFE; HKG, SHH, SHZ, JPX, OSA 15; KSC, KOE 20; rule only: NGM, NCM, ASE, BTS, CCY (FX) live, PNK 15, CME, NYM, CMX, CBT futures 10, read through `exchangeRule(exchange, symbol)`.
- `time.js`: arithmetic on fixed-offset clocks, by hand (QuickJS has no `Intl`): `MINUTE_MS`, `HOUR_MS`, `DAY_MS`, day numbers (`localDay`), weekdays (`weekdayOf`, `tradesOn`), day starts (`dayStart`), a local window as ms (`localWindow`) and New York's offset (`usOffsetMin`). Imports nothing.
- `filter.js`: the market filter (`marketFilters`, `readFilter`, `visibleSymbols`, `inFilter`, `filterAfterAdd`, `filterAfterRemove`, `heldFilter`, `dropBefore`, `nextOf`) and the copy's stored choice (`openFilter`, `FILTER_STORAGE_KEY`), in `markets.js`'s `marketOrder`. The market filter is read per render.
- `calendar.js`: Taipei days and a future's trading day (15:00 start, weekends skipped), and TWSE's holiday list (`parseHolidays`, `listsYearOf`). Also `taipeiDay`, `tradingDay`, `futuresDay`, `dayOf`, `taipeiMinute` and `taipeiAt`; day starts and windows (`dayStart`, `localWindow`, `tradesOn`) are in `time.js`.
- `closures.js`: `closureOf` is the one rules table for a row's closure, listed and inferred, as one tagged value (`closure.kind`: `listed`, `noTrades`, `nightRemoved` or `nightNoTrades`), with its next inference deadline beside it; `Watchlist#closureAt` works it out once per market and moment. Also `currentOpen`, `twMarket`, `withClosure` and `heldMarks`.
- `freshness.js`: `marketSession(quote, now)` (pre, open, post, closed) and `freshness(quote, session, now)`, RECIPE.md's Freshness table, pure (with `msUntilStale`), plus `shownLimit`; `format.js` writes their labels. The view draws only from them.
- `detail.js`: the detail dialog's view model, pure: its cells (`activityCells`, `innerOuter`, `detailBook`, `ladder`, `bookTotals`, `secondRow`), its times (`detailTimes`) and 交易時段 (`sessionTimes`, written by `sessionTimesParts`), its sources (`detailSource`), its dimming (`detailDimmed`) and its one redraw task (`detailWakeAt`, `followDetail`; see Sessions).
- `motion.js`: the timings, whole spin turns, `rowsWithGhosts` and `settleOffset`; `playRow` in `main.js` plays a row's motion. `rowsWithGhosts` keeps a removed row, from data copied before its quote goes, at its measured height and old place, unless the filter hides it; `settleOffset` starts a dropped row at `relative().top(from)`, its move in measured row heights. A native `transition` (`opacity`, `height`, `top`) animates only a later change, so `playRow` draws the start value, flips to the end 32 ms later (two `cx.sleep`s), then drops the state.
- `i18n.js`: `STRINGS`, one table per language with the same keys (`i18n/en.js`, `zh-tw.js`, `zh-cn.js`, `ja.js`, `ko.js`, each exporting its own table), and `t(lang, key, params)`, falling back to English, then the key. The tables use `{name}` placeholders; English includes `quotes.js`'s error texts. The watchlist hands the view `{ code, params }` (a removal's adds `undo`); the view translates when it draws.
- `settings.js`: `readSettings`, `validateSettings`, `mergeSettings`, the source gates and consents, `currentHealth` and what the settings pages and items show. `readSettings` checks every field, defaults otherwise; `validateSettings` maps a field path to an error code, `{}` when valid; `mergeSettings` keeps unknown keys, also inside `sources`; for the consents an older statement version counts as none; in `currentHealth` a problem seen at opening holds while the settings its source reads are unchanged. Also `upIsRed` and the key's name, `finnhub.key`.
- `providers/`: per source (`yahoo.js`, `binance.js`, `mis.js`, `yahootw.js`, `finnhub.js`) its host, kinds, batching and decoding; `provider.js`: the `Provider` type, `parseJson`, `failEach`.

## Moves

What RECIPE.md's Own tab, Docked block's own tab and Yield lines summarize, in full:

- **Own tab**: the maximize icon shows only when a Wickline pane shares the shown tab with another pane. It opens a tab named `Wickline` (`tab.new`, `props: { from: <the pane's tab>, filter }`) whose copy draws the table, and closes the old pane (`pane.close`): one copy keeps fetching. There, the restore icon splits Wickline right (`pane.split`) of a pane of the tab it came from (its focused pane, else its first terminal, else any), else of the focused pane, else of any terminal, never a Wickline pane or one in its own tab, then closes its own pane, never the tab (it goes when empty; a shell split there stays). With nowhere to go back to, the icon is hidden. Dialog copies never draw these icons. The pane copy is the focused Wickline pane in `panes()`, checked at each click.
- **Docked block's own tab**: a shown, non-yielding docked block's maximize icon runs `tab.new` with `props: { dock: true, from: <the person's tab>, filter }` (`dock` checked first: `returnPane` never reads that `from`). Once the new tab's Wickline pane shows up, it stores `shared("wickline.dockTab")` = `{ tab }` and runs `layout.hide` on the collapse node (`dockOf`: the stack, or the wrapper it alone fills, up to the first node with a sibling: `panel` in a typical docked layout; a stack straight in a row collapses alone). The block stays. The tab copy (`props().dock === true`) shows **back to the panel** while the layout has a card block: `layout.select {stack, child: block}`, `layout.show {id: collapse}`, then, once shown, clears `wickline.dockTab` (`{ tab: null }`), selects its `from` tab (`tab.select {id: from}`) while `panes()` lists it (else the focus goes to the neighbour), and runs `pane.close` on the focused Wickline pane, never `tab.close`.
- **Yield**: while `blockYields(shared("wickline.dockTab"), panes())` holds (a Wickline pane is in that tab), the docked block draws only `Wickline is open in its own tab.` and a **back to the panel** button, and its `shown()` is false. The button runs the same select, show and wait, then closes that tab's Wickline pane (`panes().find`) and clears the key. A record naming a tab with no Wickline pane never yields, so a Wickline pane opened another way (`ctrl-alt-b`), even in that tab, never makes it yield; the docked copy clears it once (`staleDockTab`, written only while stale). `dockOf` takes the first card block: Wickline is docked once.

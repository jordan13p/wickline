# Wickline — internals

Build details behind [RECIPE.md](RECIPE.md)'s Built from, needed only when rebuilding Wickline: each request and the fields it reads, the stored layouts, per-module notes beyond the module map (with how a move waits), the logos and the icon drawing, and each source's detailed rules (Yahoo TW Stock's acceptance, clock, line and TW-only rules, MIS's price rule and field notes, Yahoo's exchange codes). Hosts, programs and storage locations are named in RECIPE.md; nothing here changes them.

## Network requests

Each source's requests and the fields its decoder reads (headers, hosts and the person's URLs under RECIPE.md's Network):

- `https://query1.finance.yahoo.com/v8/finance/chart/<symbol>?interval=5m&range=1d&includePrePost=false`: `chart.result[0].meta` (`regularMarketPrice`, `regularMarketTime`, `exchangeName`, `previousClose` else `chartPreviousClose`, `currency`, `longName`/`shortName`, `regularMarketDayHigh`/`Low`, `regularMarketVolume` (none for an index; ÷1000 as lots for `.TW`/`.TWO`, else shares), `currentTradingPeriod.pre/regular/post`) and `indicators.quote[0]` (`close` for the line, the first `open`). A response whose `meta.symbol` differs from the request is rejected.
- `https://data-api.binance.vision/api/v3/ticker/24hr?symbols=["BTCUSDT",...]`: `lastPrice`, `prevClosePrice`, `openPrice`, `highPrice`, `lowPrice`, `volume` (base asset), `closeTime`.
- `https://data-api.binance.vision/api/v3/klines?symbol=BTCUSDT&interval=15m&limit=96`: closes (index 4) for the 24-hour line.
- Finnhub (chosen, key saved): `https://finnhub.io/api/v1/quote?symbol=AAPL` (or the saved Finnhub URL with `/quote?symbol=`), header `X-Finnhub-Token: <key>`: `c`, `pc`, `o`, `h`, `l`, `t`.
- Yahoo 奇摩股市 (on, consented): `https://tw.stock.yahoo.com/_td-stock/api/resource/StockServices.stockList;symbols=2330.TW,6488.TWO`: rows matched on `symbol`: `symbolName`, `regularMarketTime` (ISO), `exchangeDataDelayedBy`, `exchange`, `currency`, and as `{ raw }` (`-` when none) `price`, `regularMarketPreviousClose`, `regularMarketOpen`, `regularMarketDayHigh`/`Low`, `limitUpPrice`/`limitDownPrice`, `volumeK` (thousands: lots; a future's contracts ×1000; none for an index), and plain `previousVolumeK`, `singleVolumeK` (last size), `turnoverM` (millions; 0 is none), `avgPrice` (`-` none), `inMarket`/`outMarket` (inner/outer) and `totalMarketVolK`, scaled alike, no activity for an index. Inner and outer are kept only when their sum equals `totalMarketVolK` exactly (the totals read by `amount`: a number or plain numeric string, 0 kept, `" "`/`-` none); else both are dropped, the rest kept. `orderbook` (`bid`/`ask`, `bidVolK`/`askVolK`) with `sumBidVolK`/`sumAskVolK`: a side whose sizes (unpriced 0; an unreadable priced size fails) differ from its total drops the book; `[]`, totals 0: empty; 5 shown a side, nonpositive ones skipped. Lines: `…/FinanceChartService.ApacLibraCharts;type=tick;symbols=%5B%222330.TW%22%5D`: `[0].chart` with `meta.symbol`, `meta.currentTradingPeriod`, for a future `meta.sourceTradingPeriods` (its sessions, nested by day; kept flat and sorted as `periods.segments`), `timestamp` (s) and `indicators.quote[0].close`. The symbol's kind (`kindOf`) picks the feed clock and the day key (`tradingDay`): a future's (`WTX&`, rows from TFE only) or a stock's (stocks and indices, TAI and TWO together).
- MIS (on, consented): `https://mis.twse.com.tw/stock/api/getStockInfo.jsp?ex_ch=tse_2330.tw|otc_6488.tw&json=1&delay=0` (or the saved MIS URL with the same query): `msgArray[]` rows matched on `ex` and `c`, with `z` (last trade, `-` when none), `b`/`a` (best bids and asks, `_`-separated) with `g`/`f` (sizes, lots), `y`, `o`, `h`, `l`, `n`, `tlong` (ms), `u`/`w` (limit up and down), `v` (volume, lots; never read from a flagged row), `tv` (last size, lots, a traded row only), `ts` (`1` while the row is in a call auction) and `pz` (that auction's trial price).
- TWSE holiday schedule (while the list holds a Taiwan symbol, once per Taipei date): `https://openapi.twse.com.tw/v1/holidaySchedule/holidaySchedule`, a JSON array whose rows give `Name` (the closure's reason, trimmed) and `Date` (ROC, `1151225`: year 115 + 1911, month, day); `Weekday` and `Description` are not read. A row whose `Name` holds 交易日, 開始交易 or 最後交易 is a notice of a trading day (國曆新年開始交易日), not a closure (loose on purpose: a missed closure is still inferred); a Saturday or Sunday date is dropped; any other name is a closed weekday (市場無交易，僅辦理結算交割作業 included). Only the first fetch of a Taipei date holds a Taiwan round, by the 10 s timeout at most; a failure (also a list without a closed weekday of the current Taipei year, such as an empty one) keeps the held list and is retried 1 h after it started, beside the rounds, and never reaches the status line. Kept in memory only. A listed date reads `holiday` for stocks and indices from 00:00 Taipei; for futures from 05:00 when the weekday before ran a night session into it, else from 00:00. From 00:00 to 05:00 after a listed weekday, the night it removed reads closed (`日盤 08:45–13:45 · 夜盤休市`). A trade at or after the current session's open in any row of a market (stocks and indices: 09:00; futures: 08:45, 15:00, or the day before's 15:00 until 05:00) overrides both for every row of that market. Licence: Open Government Data License, version 1.0; its attribution statement: 「臺灣證券交易所 有價證券集中交易市場開（休）市日期（每年最新版）；此開放資料依政府資料開放授權條款 (Open Government Data License) 進行公眾釋出，使用者於遵守本條款各項規定之前提下，得利用之。https://data.gov.tw/license」
- Inferred closures (`No trades today`, `今日無成交`; never 休市, which only the schedule gives): per Taiwan market and session (stocks and indices: 09:00; futures: 08:45, and 15:00 until 05:00), a copy keeps in memory the newest trade any answer carried (whatever its day; the session has traded once it is at or after the open) and each source's latest answer: when it arrived and whether the source is real time. Yahoo 奇摩股市's stock list reports `newestTrade` per market clock: the newest `regularMarketTime` among the requested rows with a positive price, a trade time the decoder accepts (a future's at most 5 min ahead, a stock's not after today) and `exchangeDataDelayedBy` 0 (futures only from TFE), so a delayed or `-` row is neither an answer nor a trade; MIS each quote's `tlong` when `z` priced it (a book price, or a row flagged in a call auction, is a snapshot, no trade, so a closed, `休市` or `今日無成交` label over it has no time, only an earlier day's date), Yahoo Finance each Taiwan quote's time (real time by its exchange). Only sources that are on count, listed real time first, each kind in `PROVIDERS` order (Yahoo 奇摩股市, MIS, Yahoo Finance): turning one off drops its reading and note at once. A session reads no trades from its open + 10 min with a real-time answer, or + 30 min with a Yahoo Finance one (20 min late), each only when that kind's latest answer arrived at or after the deadline − 2 min, so one answer at the open and then an outage never counts; the first counting answer names the source on the status line, so the note never alternates. The deadlines are row edges (`closureOf` gives the next one beside the closure, carried as `closureDeadline`): a redraw, not a round. Veto: a futures trade since 08:45 (the night answers' newest included, for a copy shown after 15:00) blocks a stock inference; a stock trade since 09:00 blocks the futures day session's. The night: after a day that traded (its day session, the night answers' newest trade at or after 08:45, or stocks since 09:00), the closure `nightNoTrades`: `已收盤 · 13:45`, `日盤 08:45–13:45 · 夜盤尚無成交`, and `<source> 夜盤尚無成交。`; after a day without trades, `今日無成交` again. On such a day the day session's reading carries from 15:00 to the night's deadline (15:10, a row edge also when no night answer comes), and from 00:00 to 05:00 the night's reading of the day before holds (`今日無成交` until 05:00), unless the new date is listed (休市). A listed day comes first; a trade since the open clears everything at once; a weekend never reads it.

**Yahoo 奇摩股市** (off by default): the same overlay for Taiwan stocks and indices (symbols URL-encoded), from the fixed `tw.stock.yahoo.com`, with its own switch and consent, whose statement names what is asked by exchange (TWSE, TPEx, TAIFEX) (`sources.tw.yahootw`, `yahootwAck.version` = `YAHOOTW_CONSENT_VERSION`, 2; a MIS consent never counts). A row is priced only with a positive price, its trade on today's trading day in Taipei (UTC+8 by hand) and `exchangeDataDelayedBy` 0; a `-` row gives only its name. A future's row counts only from `exchange` TFE (any other gives nothing, its name ignored, so it reads not found) and is never discarded for its limits (still kept for lighting). A price outside its own `limitDownPrice`..`limitUpPrice` is discarded with a reason, and so is a priced row of a symbol priced here alone (below) that is delayed, has no trade time or is over 5 min ahead (`Yahoo TW Stock returned no real-time prices.`); any other rejected row, or a symbol missing from the answer, gives nothing; while open, an answer with prices but none accepted (not `-` only) says on the status line it returned no real-time prices, until one is priced. A future (`^[A-Z]{1,6}[&@]$`, such as `WTX&`; market Taiwan by its form) is TW-only by form: priced here alone, never sent to Yahoo Finance, MIS or Finnhub; with this source off it is one unavailable line, `Futures quotes need Yahoo TW Stock turned on in Settings.`, or the re-confirm reason while its consent awaits re-confirmation (a TW-only index too, in place of not found), gone as soon as the source is on; a code it does not answer reads `Ticker not found on Yahoo TW Stock.`. No other unknown symbol is sent.

Yahoo 奇摩股市, past the request above: A future's row counts only while at most 5 min ahead of the local clock, on any day (so for today from a later day too: a clock a little behind Yahoo's at 15:00); a future's trading day starts at 15:00 in Taipei and is the next weekday's (Friday night is Monday's), holidays unknown. Every row priced today is timed at the newest of today's trades on its own market clock: futures (TFE) on theirs, stocks and indices (TAI and TWO together, whatever `exchange` says) on the stock clock, so a quiet stock never takes a night futures trade (`tradeTime` keeps its own). Its line (the trading day's one-minute closes, a future's from 15:00 the day before, so the night's minutes stay past midnight; a quiet minute carrying the last close, leading empty minutes and any after now (a future's answer lists the whole day) dropped; `meta.symbol` must match) replaces Yahoo's only while its price is shown and of the line's day, ending at that price. A failed, empty or frozen line (on arrival, its last minute with a close over 2 min before the newest trade seen at this or an earlier arrival whose minute ended over 2 min ago, as a line holds a trade only once its minute ends, that trade capped at the end of the line's regular session (the answer's `currentTradingPeriod`, else the symbol's known periods), so a stock's 14:30 fixed-price trade never counts; so with lines 2 min apart a frozen line goes 4 min after its first arrival, 485-595 s after it stops mid-session, at once if first asked after the close over 3 min after the last trade, and stays gone, also through a dropped price), or losing the price, drops the line; a source failure also shows on the status line until that symbol's next line arrives. A `^TW…` index Yahoo Finance lacks is priced here alone while on (TW-only, in memory): market from its `exchange`, session from its line's `currentTradingPeriod`, an earlier day's row as its closed quote at its own time, not found until priced or named. Once priced, a TW-only row keeps its last price through a failed round or a rejected or missing row (shown cached, with the reason) and through a name-only answer (unmarked).

TWSE MIS, past the request above: The price is the last trade (`z`); with none in the last 5-second snapshot, the midpoint of the best bid and ask, skipping `0.0000` levels. One side only: a stock locked at its limit is priced at it (asks only, best at limit-down `w`; bids only, best at limit-up `u`; both limits present); any other one-sided row has no price, no error. A row flagged in a call auction (`ts` `1` with a snapshot time, whatever `pz` reads: from 08:30 to the open, from 13:25 to the close) is neither a price nor an error, whatever its book: the MIS price held from before it stays, else the row shows Yahoo's quote. A copy keeps the flagged snapshot's `tlong` per symbol in memory (`auctionAt`), unless the held MIS price is newer (an answer MIS's cache served late); a MIS answer that prices the symbol or no longer flags it, a failed MIS request and MIS turned off drop it. While the flag is under 2 min old (`auctionFlagged`, its only reading), the held MIS price never outranks a Yahoo 奇摩股市 price of the same Taipei day, whatever their ages, and a row whose shown price traded before the snapshot reads `auction` (`Watchlist#marked` passes `auctionAt` then). A Yahoo 奇摩股市 trade at or after the snapshot ends it. A names-only row (before 08:30: no `ts`, no `pz`) is no flag. Levels: 5 a side, nonpositive prices (`0.0000`) or sizes skipped: a priced row's `book`; a flagged row's `auctionBook`, kept as `auctionBooks` with `auctionAt` by the newest flag; a named row neither flagged nor priced without one: `noLevels` (an empty book) until MIS answers otherwise, fails or is off. Only symbols asked for are accepted. Codes keep case (`tse_00632R.tw`; lower case gets an empty answer). `provider` (0.3.1's key) is written from `mis` on every save and wins on load (a downgrade keeps the choice).

## Sessions

Futures (`WTX&`): sessions from the line's `sourceTradingPeriods` while `now` is on their own trading day, else TAIFEX's hours (night 15:00–05:00, day 08:45–13:45, Taipei, each opening Monday to Friday, but not on a listed closed day, whose night reads closed). Inside a session the real-time rules apply (`Live`; the day close with no night trade reads `報價停在 13:44` from 15:00, asked every 10 s, then closed from 15:10); between sessions, and over the weekend, it reads closed with its last trade time (`已收盤 · 05:00`), with no stale check and no wake for one.

The open detail fetches nothing, so it keeps the closure mark it opened with only until the mark's end (`closureUntil`, which `closureOf` in `calendar.js` gives beside the mark from the same rules table), then reads the quote without it:

| Mark | Read at (Taipei) | Ends |
|---|---|---|
| any stock mark | any time | the next 00:00 |
| a future's `listed` | any time | 05:00 the next day (the night it removes) |
| a future's `noTrades`, `nightNoTrades`, `nightRemoved` | 00:00–05:00 | 05:00 that day |
| a future's `noTrades` | 05:00–15:10 | 15:10 that day |
| a future's `noTrades`, `nightNoTrades` | 15:10–24:00 | 05:00 the next day |

An open detail wakes, one task at a time, at the earliest of its quote's next edge, its mark's end and the stale moments of what it shows a state for (a real-time price, not a pair's; a line that is another source's real-time quote), none for a quote that already reads stalled (a cached one); never at an inference deadline, since it gets no new answers; each sleep is at most 10 min and then rereads the clock; it redraws only when a wake is reached and ends with the dialog.

## Stored layouts

The storage RECIPE.md lists, field by field:

- `shared("wickline.settings.v1")`: `{ version: 1, language: "en"|"zh-TW"|"zh-CN"|"ja"|"ko", colors: "auto"|"red-up"|"green-up", languagePromptDismissed, keyRev, sources: { us: { provider: "yahoo"|"finnhub", finnhubUrl, budgetPerMinute }, tw: { mis, yahootw, misUrl, misAck: { version } | null, yahootwAck: { version } | null, provider: "yahoo"|"mis" }, crypto: { binanceUrl } } }`.

- `localStorage` `wickline.filter`: `all`, `us`, `tw`, `hk`, `cn`, `jp`, `kr`, `crypto` or `other`; each use in a `try`.

## Modules

Notes beyond each module's line in RECIPE.md's Built from:

- `main.js`: the `View` is `gpui-kit`'s `View`, with `gpui-base` `v_flex`, `h_flex`, `InputState`. The detail dialog opens with `openOverlay({ mod: "wickline", kind: "dialog", width, props: { detail, token, wide } })` (`wide`: `canCarryBook(detail, settings)` in `layout.js`, 720 else 440; the dialog keeps it) (`ui/detail-dialog.js`; `detail` is `Watchlist#detailQuote`: the row's quote as shown, with its `error`, its overlay's `fallback` and its mark's end `closureUntil`, read at one moment), the settings dialog as a modal one with `settings: { tab, health }` (`ui/settings-dialog.js`); draft, inputs and Save stay on the view. `openDetail` writes before `openOverlay`; each loop's `changed` runs `handOver` (one synchronous step); `render` adopts (`adoptDetail` wakes `followDetail`); `close` clears its own. Only `detailStore` touches the key.
- `handover.js`: `nextWrite` writes `seq + 1` while the key holds its token and `contentKey` differs: the quote, or, paused, all but `closure`/`closureUntil` (paused loops re-mark rows at each edge). `adopt`: own token, higher `seq`.
- `ui/`: built from `gpui-kit` `div`, `svg`, `PathBuilder`, `Background`, `window.paint_path` and `gpui-base` `h_flex`, `v_flex`, `Input`, `Checkbox`, `Switch`. `rowFrame` holds the handle, `×`, hairline and drop line. `chart` paints each by `window.paint_path(...)` as an absolute layer over a sized `div`: the line (`PathBuilder.stroke`, 2px with the fill by default, else 1.25px; 1.5px in the sidebar and table), the rule (`.dash_array([3, 3])`), the fill (`PathBuilder.fill()`, closed along the bottom to the line's end), both only with 2 or more points; the price's dot is an absolute `rounded_full` `div` (4px, `{ dot: 6 }` in the detail) in a layer inset by half its size, so it stays whole at either end. `chartGeometry(series, reference, chartLayout(quote))` (`format.js`) spreads the points over the extent as `[x%, y%]`, 8% headroom, the previous close (whenever positive) and the dot in range; `chartLayout` and `sessionProgress` (`freshness.js`) give the extent and the dot from the trading day: the regular period or the exchange's hours less lunch, a future's two segments of its trading day (its periods', else TAIFEX's), none for a pair, FX or `=F`. The detail dims (`detailDimmed`: cached or stalled) with one `opacity(0.5)` each on its price line and activity (one column's volume; two's grid, inner/outer bar and book; ladder digits in `LADDER_FONT`).
- `watchlist.js`: the host's `shown()` defaults to true and comes from `layout()` for a docked block. `main.js` runs each source's `runProvider(id, io)` in its own `cx.spawn`, with its `cx.sleep` and `cx.notify()`. Each source keeps a cooldown and a problem (`problems()`: status lines, the dialog's `health`) and quotes the symbols of its markets and kinds, within its `cap` (first in list order). An overlay source writes its own prices and errors (by symbol, then source), never the base quotes; the `line` a row merges is that source's same-day line or the base's, the latter only when the base's time and the overlay price's are on the same side of the base's regular period's start (else no line, no `chartSource`, no `chartCached`). A source that is a symbol's sole source (Yahoo 奇摩股市 for a TW-only symbol or a future) gives that row its errors and periods; its price stays in the source's own slot. An index whose market resolves wakes each overlay source it joins, never a full restart. The Finnhub key, reread when `keyRev` changes, stays in memory and requests, never `config()`. Edits (`restore` undoes `remove`) are synchronous, bump a revision (a round in flight drops its late results) and wake every loop, as `sync()` does for another copy's edit. A source declares `id`, `markets`, `kinds`, `overlay`, `cap(config)`, `manualRefresh`, `spacingMs`, `intervalMs`, `linesMs`, `linesPerRound`, `requests` and `decode` (`providers/provider.js`); `Watchlist.serves` decides which symbols it gets, and a `QuoteError` with `stopsSource` stops its loop. Between rounds a loop also wakes at the shown rows' next edge (`edgeAt`, from `freshness.js`'s `nextEdge`; `{ openings: true }` for openings only), the moments a row's session or day can turn: a period's pre, regular and post bounds (else a Taiwan or US quote's exchange hours on a trading weekday; not FX), the exchange's lunch inside the regular period, a future's segments (its line's and TAIFEX's table, which alone holds the 15:00 night once `ownPeriods` drops the line's), FX's Friday and Sunday 22:00 UTC, each row's own midnight (Taipei for a Taiwan row, else local; DST-safe), and for a Taiwan stock with a real-time source on (`twRealtime`) the call auctions' edges (08:30, 09:00, 13:25, 13:30 Taipei on today's and the next Taipei date, each only on a weekday; none on a listed day) and MIS's flag lapse (`auctionAt` + 2 min). Openings (a regular start, a lunch's end, a segment's start, FX's Sunday 22:00) also end the interval and start a round; any other edge only redraws. A hidden copy skips edges until `wakeMissed()`. Activity (`ACTIVITY_FIELDS`): `mergeOverlay` drops the base's unless the overlay is its source, or sends no volume over a real-time base (`isRealtime`: Finnhub's `AAPL` keeps Yahoo's); `marked` drops a Yahoo Taiwan stock's while a real-time source is on, then the book (`rowBook`): a held row's auction book, else its own (a stock's Yahoo 奇摩股市 book fetched from `auctionWindowStart` on: `auction`), else empty under `noLevels`.
- `secrets.js`: the `system` holds `platform()` (from `window().platform`) and `chmod(path)`, the one `exec` under Programs, run after each write on `macos` and `linux` only; the folder is `appHome()` + `/data/wickline`. The file goes with its last key; save and remove resolve false when chmod failed (the key is still written).
- `layout.js`: `TABLE_COLUMNS` (id, width, alignment); `tableColumns(width)` gives the ids that fit, in display order; `nameWidth`.
- `moves.js`: runs only `tab.new`, `tab.select`, `pane.split`, `pane.close`, `layout.hide`, `layout.show` and `layout.select`. Its `syncDock` (from `render`, for the view) and `onScreen` (for the loops) read the block's place, yield and shown state, both clearing a stale `wickline.dockTab`.
- **Moves wait**: the old copy closes (or the block collapses) only once `panes()` or `layout()` shows the new place: a new Wickline pane outside the old tab (in the target tab going back), one in a tab that did not exist before (`newWicklineTab`; `ctrl-alt-b` into an existing tab never counts), or the panel shown (`isShown`). A task looks every 50 ms for about 1.5 s; failing that, nothing closes, collapses or is stored, and the icon works again. While a move waits, clicks do nothing (`moving`).
- `markets.js`: `marketOf` judges by form; the kinds are stock, index, pair, future (`WTX&`, Taiwan by form) and other. `exchangeRule(exchange, symbol)` gives `{ realtime, delayS, lunch, futures, fx }` (`.TW`/`.TWO` TAI's if unlisted, `=F`/`=X` without one); `TYPICAL_EXCHANGE` (us NMS, tw TAI). `TAIFEX_HOURS` is TAIFEX's own table (day 08:45–13:45, night 15:00–05:00, Taipei minutes, Monday to Friday openings), apart from Yahoo Finance's `RULES`: `freshness.js` reads a future's session from its line's segments, else from it (`futuresSegment`, `sessionName`), and `watchlist.js` cuts a wait at its next opening (`edgeAt`, from `freshness.js`'s `nextEdge`). `TWSE_HOURS` (09:00–13:30 Taipei, TWSE and TPEx) and `US_HOURS` (09:30–16:00 New York, its offset from `usOffsetMin`: daylight saving by hand, second Sunday in March to first Sunday in November) give a Taiwan or US quote its session only until Yahoo's periods arrive (`hoursWindow` in `freshness.js`); a today's price that had stalled by the close keeps reading stalled after it, never closed (`stoppedBeforeClose`); any other market stays unknown, and the view shows no word for it. `ownPeriods` drops a line's `segments` once `now` is on a later trading day than theirs, so from 15:00 the night is read from the table. The market filter is read per render. Yahoo's exchange codes (closed): US DJI, SNP, NIM, NMS, NYQ, PCX live, CXI 20, NYS, WCB 15; Taiwan TAI, TWO 20, TFE; HKG, SHH, SHZ, JPX, OSA 15; KSC, KOE 20; rule only: NGM, NCM, ASE, BTS, CCY (FX) live, PNK 15, CME, NYM, CMX, CBT futures 10, read through `exchangeRule(exchange, symbol)`.
- `calendar.js`: `taipeiDay`, `tradingDay`, `futuresDay`, `dayOf`, moved from `providers/yahootw.js`, and `taipeiMinute` and `taipeiAt` (day starts and windows, `dayStart`, `localWindow` and `tradesOn`, live in `markets.js`); `closureOf` is the one rules table for a row's closure, listed and inferred, as one tagged value (`closure.kind`: `listed`, `noTrades`, `nightRemoved` or `nightNoTrades`), with its next inference deadline beside it; `Watchlist#closureAt` works it out once per market and moment.
- `motion.js`: `rowsWithGhosts` keeps a removed row, from data copied before its quote goes, at its measured height and old place, unless the filter hides it; `settleOffset` starts a dropped row at `relative().top(from)`, its move in measured row heights. A native `transition` (`opacity`, `height`, `top`) animates only a later change, so `playRow` draws the start value, flips to the end 32 ms later (two `cx.sleep`s), then drops the state.
- `i18n.js`: the tables use `{name}` placeholders; English includes `quotes.js`'s error texts. The watchlist hands the view `{ code, params }` (a removal's adds `undo`); the view translates when it draws.
- `settings.js`: `readSettings` checks every field, defaults otherwise; `validateSettings` maps a field path to an error code, `{}` when valid; `mergeSettings` keeps unknown keys, also inside `sources`; for the consents an older statement version counts as none; in `currentHealth` a problem seen at opening holds while the settings its source reads are unchanged. Also `upIsRed` and the key's name, `finnhub.key`.

## Moves

What RECIPE.md's Own tab, Docked block's own tab and Yield lines summarize, in full:

- **Own tab**: the maximize icon shows only when a Wickline pane shares the shown tab with another pane. It opens a tab named `Wickline` (`tab.new`, `props: { from: <the pane's tab>, filter }`) whose copy draws the table, and closes the old pane (`pane.close`): one copy keeps fetching. There, the restore icon splits Wickline right (`pane.split`) of a pane of the tab it came from (its focused pane, else its first terminal, else any), else of the focused pane, else of any terminal, never a Wickline pane or one in its own tab, then closes its own pane, never the tab (it goes when empty; a shell split there stays). With nowhere to go back to, the icon is hidden. Dialog copies never draw these icons. The pane copy is the focused Wickline pane in `panes()`, checked at each click.
- **Docked block's own tab**: a shown, non-yielding docked block's maximize icon runs `tab.new` with `props: { dock: true, from: <the person's tab>, filter }` (`dock` checked first: `returnPane` never reads that `from`). Once the new tab's Wickline pane shows up, it stores `shared("wickline.dockTab")` = `{ tab }` and runs `layout.hide` on the collapse node (`dockOf`: the stack, or the wrapper it alone fills, up to the first node with a sibling: `panel` in the office layout; a stack straight in a row collapses alone). The block stays. The tab copy (`props().dock === true`) shows **back to the panel** while the layout has a card block: `layout.select {stack, child: block}`, `layout.show {id: collapse}`, then, once shown, clears `wickline.dockTab` (`{ tab: null }`), selects its `from` tab (`tab.select {id: from}`) while `panes()` lists it (else the focus goes to the neighbour), and runs `pane.close` on the focused Wickline pane, never `tab.close`.
- **Yield**: while `blockYields(shared("wickline.dockTab"), panes())` holds (a Wickline pane is in that tab), the docked block draws only `Wickline is open in its own tab.` and a **back to the panel** button, and its `shown()` is false. The button runs the same select, show and wait, then closes that tab's Wickline pane (`panes().find`) and clears the key. A record naming a tab with no Wickline pane never yields, so a Wickline pane opened another way (`ctrl-alt-b`), even in that tab, never makes it yield; the docked copy clears it once (`staleDockTab`, written only while stale). `dockOf` takes the first card block: Wickline is docked once.
